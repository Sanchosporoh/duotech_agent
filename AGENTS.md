# Правила работы над проектом

- Пользователь занимается интегрированным моделированием и имеет навыки программирования, но не является профессиональным разработчиком.
- Всегда выбирать самое простое решение, которое решает текущую задачу.
- Объяснять архитектуру и код простым инженерным языком, новые термины сразу расшифровывать.
- Не добавлять LLM туда, где достаточно обычного алгоритма или готового расчётного кода. При этом исходное распределение шагов между LLM и обычным кодом можно менять, если есть понятное инженерное обоснование.
- Развивать проект небольшими проверяемыми шагами, без преждевременных микросервисов и сложной инфраструктуры.
- Первый прототип не использует локального субагента: прогноз считается заранее подготовленной функцией.
- Оптимизация должна учитывать синтетический реестр возможностей, подготовленный внешней методикой модели ограничений.
- Мероприятия реестра уже проверены моделью ограничений. Проект применяет к ним новые глобальные ресурсные и экономические ограничения.
- Отсутствие свежего факта не считать отклонением добычи и не запускать оптимизацию.
- На этапе MVP внешнее действие имитируется записью в локальный файл-реестр. Создание задач в Битрикс включается только на финальной стадии, чтобы тестовые прогоны не создавали реальные задачи.
- Каталог `C:\work-scripts\Pssport_IMA` и всё его содержимое запрещено изменять. Не читать и не анализировать его без отдельного явного разрешения пользователя; при необходимости запросить локальную копию.
- Исходные файлы PetEx в `IM_2022_06` использовать только на чтение. Любые расчёты, способные сохранить изменения в модели, выполнять только на рабочей копии.
