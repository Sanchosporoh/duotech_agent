# Агент мониторинга и оптимизации добычи

Учебный MVP автономно проходит производственный цикл:

1. Получает почасовой план, факт сепаратора и доступную телеметрию скважин.
2. Проверяет свежесть и физическую корректность измерений.
3. Открывает инцидент при выходе добычи за допустимый диапазон.
4. Формирует конкурирующие диагностические гипотезы через Codex CLI.
5. Проверяет гипотезы обычным кодом и, когда необходимо, моделью PROSPER.
6. Выбирает кандидатов из заранее подготовленного реестра возможностей.
7. Проверяет точные режимы и сетевые ограничения в GAP.
8. Предлагает лучший достижимый вариант инженеру, но не утверждает его самостоятельно.
9. После утверждения имитирует исполнение записью в локальный реестр.

LLM применяется только там, где нужен выбор и объяснение гипотез или наборов мероприятий. Контроль качества, расчёт баланса, ограничения и исполнение выполняются детерминированным кодом.

## Архитектура

- `src/` — логика мониторинга, диагностики, планирования, жизненного цикла инцидента и HITL;
- `dashboard.py` — интерактивная витрина Streamlit;
- `tools/` — генераторы данных, проверки и адаптеры PROSPER/GAP;
- `tests/` — автоматические тесты;
- `data/` — демонстрационные входы и обезличенные результаты;
- `system-dataflow-20260921.html` — интерактивная схема потоков данных;
- `process-archify.html` — схема производственного процесса.

HITL означает «человек в контуре»: окончательное решение об исполнении остаётся за инженером.

## Передача другому кодовому агенту

- `CLAUDE.md` — постоянные инструкции для Claude Code;
- `docs/CLAUDE_HANDOFF.md` — инженерный контекст, карта модулей, готовность и следующие задачи;
- `AGENTS.md` — обязательные общие правила проекта.

Claude Code следует запускать из корня репозитория, чтобы он автоматически прочитал `CLAUDE.md`.

## Что такое очередь

Очередь — это обычный список случаев, которые программа не смогла обработать автоматически. Например: нет данных, расчёт завершился ошибкой или результат требует решения инженера. В первой версии отдельной системы очередей нет: такие случаи записываются в журнал запуска со статусом `needs_attention`.

## Установка и запуск

Требуются Python 3.10 или новее, установленный Codex CLI и, для модельных расчётов, PetEx OpenServer с лицензиями.

```powershell
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
start_dashboard.bat
```

Локальный экран без запроса email:

```powershell
python -m streamlit run dashboard.py --server.port 8503
```

Агент работает отдельным процессом, без витрины:

```powershell
start_agent.bat                                                     # демо: один учебный час в минуту до 23:00
C:\work-scripts\venv\Scripts\python.exe tools\run_agent.py --once          # один такт
C:\work-scripts\venv\Scripts\python.exe tools\run_agent.py --loop --clock wall --interval 300   # реальное время
C:\work-scripts\venv\Scripts\python.exe tools\run_agent.py --reset         # начать сутки заново
```

Каждый такт пишет запись в `data/live/runs/` (час, итог, стадии инцидентов, длительность, ошибки), часы агента хранятся в `data/live/clock.json`. Витрина только читает записанное агентом, сама обновляется при новом часе и принимает решение инженера. Кнопка «Обработать следующий час сейчас» вызывает тот же такт вручную для демонстрации без планировщика. `AGENT_PROJECT_ROOT` открывает витрину на отдельной копии проекта (например, для режима заглушек).

После формирования гипотез обычный Python-код сравнивает первые и последние шесть часов по указанным скважинам. Он рассчитывает изменение дебита, давления, тока и вибрации и независимо присваивает результат `supported`, `not_supported_by_current_data` или `insufficient_data`. Результаты доступны на вкладке «Проверка гипотез».

Утверждённое решение создаёт запись в локальном реестре. Это безопасная имитация будущей задачи Битрикс. Повторный запуск не создаёт дубль. Реальная интеграция с Битрикс остаётся выключенной.

Программа создаст папку `runs/<run_id>` и сохранит туда:

- `input.json` — синтетические исходные данные;
- `result.json` — решение и объяснение;
- `run.log` — короткий журнал выполнения.

## Важные ограничения MVP

- исходные данные пока учебные;
- реестр возможностей считается результатом внешней методики модели ограничений;
- точные режимы и интерференция проверяются в GAP только для выбранных кандидатов;
- PROSPER/GAP требуют локальной установки PetEx и действующих лицензий;
- модели PetEx, рабочие копии, расчётные кэши и локальные решения намеренно исключены из Git;
- отсутствие свежего факта блокирует диагностику и оптимизацию;
- рекомендация не исполняется без решения инженера.

## Проверка

```powershell
C:\work-scripts\venv\Scripts\python.exe -m unittest discover -s tests -q
```

Python окружения проекта: `.venv\Scripts\python.exe`, если создано, иначе общее `C:\work-scripts\venv\Scripts\python.exe`. Системный `python` может не иметь зависимостей (pandas, streamlit). Тесты не читают `data/live/`: временный проект создаётся в `tests/support.py`.

Режим заглушек `AGENT_TOOL_BACKEND=stub` проходит всю цепочку без Codex и PetEx. Он разрешён только в отдельной копии проекта, не в рабочем каталоге; витрина показывает предупреждение. Результаты заглушек не являются расчётом.

## Синтетические таблицы

- `production.csv` — 40 часов суммарного плана и факта по кусту;
- `well_telemetry.csv` — 40 часов по каждой из четырёх скважин;
- `events.csv` — производственные события и аварийные сигналы;
- `physical_rules.csv` — шаблон физических проверок;
- `opportunities.csv` — готовый реестр технически допустимых мероприятий;
- `global_constraints.csv` — новые ограничения верхнего уровня.
- `petex_well_reference.csv` — справочник 17 скважин из текстовых отчётов PROSPER;
- `petex_source_inventory.csv` — состав переданного комплекта PetEx и способ чтения файлов;
- `petex_gap_calculation_logs.csv` — доступные результаты журналов GAP.

Сценарий можно полностью пересоздать командой `python tools/generate_synthetic_data.py`. При каждом запуске получаются одинаковые значения, поэтому результаты удобно сравнивать.

Справочник PetEx обновляется командой `python tools/extract_petex_reference.py`. Скрипт читает только `.tpd` и `.gaplgs` и не изменяет рабочие модели.
